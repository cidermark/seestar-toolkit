# Test Data

This directory contains a small set of curated FITS files used during
development and testing.

## seestar/

Real FITS pixels produced by the ZWO Seestar, with sanitised public headers.

- light.fit
- eq.fit
- mosaic.fit
- mosaic_1.fit
- mosaic_4.fit
- mosaic_6.fit
- stacked.fit
- stacked_mosaic.fit

## reference/

Real and synthetic reference FITS files for third-party software layouts.

- `siril_stacked.fit`: real Siril standard-stack pixels with a sanitised header.
- `siril_stacked_mosaic.fit`: synthetic public Siril-style mosaic, 5,760 bytes.

These files are intentionally kept small and stable. They form part of the
project's regression test data and should not be replaced without good reason.

## Synthetic Siril mosaic

The active mosaic fixture replaces the historical 272,923,200-byte real Siril
mosaic during Stage 9.1d preflight. It is generated by Astropy, not by Siril;
`PROGRAM=Siril synthetic fixture` makes that provenance explicit.
Regenerate from the repository root with the development environment active:

```bash
python tools/generate_siril_mosaic_fixture.py
```

It has one primary image HDU, `BITPIX=-32`, channels-first float32 shape
`(3, 17, 11)` (width 11, height 17), `IMAGETYP=Light`, and no Bayer or
row-order keyword. Invented rotated TAN WCS retains the orientation context
of the original mosaic without copying its sky coordinates. The toolkit
uses the shared RGB path and must not rotate, flip, demosaic or stretch it.

Pixels are deterministic linear values:
`(channel * 256 + row * 12 + column) / 1024`. Distinct channel, row and column
values reveal channel swaps and orientation errors; exact binary fractions
allow exact equality checks. All values are finite and within `[0, 1]`.
The integration tests retain dtype, layout, TIFF tags, full-image equality
and source-preservation checks, with an additional independent pixel oracle.

The generator reads no original image or header. Metadata is limited to FITS
structure, synthetic labels and invented WCS; there are no real locations,
capture timestamps, device identifiers, personal paths or capture history.
The original dimensions and real image are unnecessary for current contracts.
Historical stage documents retain their original real-data observations;
the old Git object remains in history pending separately authorized remediation.


## Public-fixture privacy

All nine real fixtures have sanitised headers: site coordinates, individual
device identifiers and capture/creation timestamps use explicitly synthetic
values. Pixel bytes and processing metadata are unchanged. See
[the privacy review](PRIVACY_REVIEW.md) for field inventories, exact sizes,
per-fixture test dependencies and preservation evidence. These files remain
real-image regression fixtures, not evidence of actual capture dates/sites.
