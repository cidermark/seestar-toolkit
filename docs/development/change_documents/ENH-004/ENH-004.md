# ENH-004 — Archive-Aware FITS-to-TIFF Conversion

**Specification date:** 2026-10-27

**Status:** Approved — implementation authorised.

**Approved implementation structure:**

- ENH-004a — Archive recognition and destination inference foundation
- ENH-004b — Single-file and batch CLI integration
- ENH-004c — Documentation, regression validation and implementation completion

**Git ownership:** User controls branch creation, commits, pushes, merges and
branch deletion.

## 1. Purpose and baseline

ENH-004 adds archive-aware destination inference to the existing standalone
FITS-to-TIFF commands. It does not alter archive creation, archive execution,
or the FITS-to-TIFF conversion engine.

The commands retain their existing explicit-destination forms:

```text
seestar-toolkit convert INPUT_FITS OUTPUT_TIFF
seestar-toolkit convert-batch INPUT_DIR OUTPUT_DIR
```

They gain these approved forms:

```text
seestar-toolkit convert INPUT_FITS
seestar-toolkit convert-batch INPUT_DIR
```

For a recognised current archive observation, an omitted output is inferred as
`observation_NN/tiff_images/lights/`. Explicit destinations retain their
existing meaning and collision protection.

This approved specification was prepared on repository `seestar-toolkit`,
branch `main`, at `c5fafd18eb6df84e50f71cc0fce80ed321c6531e`, which exactly
matches the stated reference baseline. The working tree was clean at
inspection. Implementation is authorised only through the approved ENH-004a,
ENH-004b, and ENH-004c structure; Git integration remains under user control.

The controlling archive layout, established by ENH-003, is:

```text
observation_NN/
├── fits_images/
│   └── lights/
├── seestar_stacked/
│   ├── <stack>.fit
│   └── <stack>.tiff
└── tiff_images/                 # lazy; only when light TIFFs exist
    └── lights/
```

Historical `observation_NN/lights/` and `observation_NN/tiff/` layouts are not
current layouts and are outside this enhancement.

## 2. Scope

### Included

1. Optional output destination for `convert` only when its input is an
   individual archived light under a recognised current observation.
2. Archive observation input recognition for `convert-batch` at the
   observation, `fits_images`, and `fits_images/lights` levels.
3. Inference of the current archive light-TIFF destination when a standalone
   command's output destination is omitted.
4. Lazy inferred-directory creation only for a valid conversion that needs it.
5. Clear diagnostics, existing reporting conventions, and existing exit-code
   semantics.
6. Focused tests, regression coverage, help and documentation updates during
   the separately authorised implementation phase.

### Excluded

- Archive creation, organisation, migration, reconciliation or recursive
  archive conversion.
- Historical-layout support, including `observation_NN/lights`.
- A `convert-archive` command.
- Changes to `archive`, `archive --convert-lights`, ENH-003 collision policy,
  or archive TIFF processing.
- Changes to FITS inspection, decoding, demosaicing, RGB normalisation, TIFF
  generation, verification, replacement, or collision policy.
- TIFF regeneration, digest comparisons, automatic skipping, renaming or
  replacement.
- Configuration additions, dry-run support, exit-code additions, telescope
  identity changes, anonymisation, other camera sources, Solar/Lunar/planetary
  support, or Siril integration.

Unrelated defects found during implementation must be reported and separately
dispositioned.

## 3. Existing boundaries and compatibility contract

`convert_fits_to_tiff(input_path, output_path)` remains the authoritative
single-file conversion boundary. It continues to receive exactly one explicit
input and destination. It owns FITS reading, supported-layout handling,
demosaicing/RGB normalisation, and TIFF writing; ENH-004 must not duplicate or
move those responsibilities.

`convert-batch` remains a flat, non-recursive orchestration layer: after any
approved archive-input resolution, it scans only the resolved lights directory,
selects case-insensitive `.fit` and `.fits` filenames, processes them in
filename order, and maps each stem to `<stem>.tiff` in one output directory.

The implementation must preserve:

- all existing explicit-output single-file behaviour, with no new extension
  restriction on `convert INPUT_FITS OUTPUT_TIFF`;
- ordinary non-archive batch conversion when an explicit output is supplied,
  and its clear operational inference failure when it is omitted;
- existing FITS decoding and TIFF generation;
- existing standalone exclusive-create TIFF collision protection;
- existing archive behaviour, including `archive --convert-lights`; and
- exit codes: `0` complete success, `1` operational failure (including partial
  batch failure), and `2` command-line usage error.

No new exit code is permitted.

## 4. Archive recognition and safety

Archive recognition is structural and is deliberately distinct from validation
that a FITS file is convertible. It uses the fixed internal ENH-003 observation
structure only. It must:

- recognise an observation directory matching the established
  `observation_NN` naming convention;
- require the current `fits_images/lights` path for light input;
- not require `INDEX.md`, configurable target/location/date ancestor
  validation, `tiff_images/lights`, or `seestar_stacked`;
- not inspect FITS content merely to infer a destination;
- reject historical layouts and paths outside a recognised observation; and
- avoid unsafe symbolic-link traversal during archive inference.

The implementation must use safe path/containment checks before treating paths
as observation structure. A symbolic link must not let an input, resolved
lights directory, or inferred destination escape the recognised observation or
cause archive inference to follow an unsafe target. A missing lights directory
is an error. An existing empty lights directory is structurally valid and is an
empty batch, not an inference error.

Recognition alone neither asserts that a file is a valid FITS nor creates any
directory.

## 5. Single-file command contract

The grammar becomes:

```text
seestar-toolkit convert INPUT_FITS [OUTPUT_TIFF]
```

When `OUTPUT_TIFF` is supplied, retain current behaviour unchanged.

When it is omitted, the command must only infer a destination when
`INPUT_FITS` is an individual file directly in:

```text
observation_NN/fits_images/lights/
```

The input suffix must be `.fit` or `.fits`, case-insensitively. Preserve its
filename stem and infer:

```text
observation_NN/tiff_images/lights/<input-stem>.tiff
```

Inference must reject a stack FITS (including any input under
`seestar_stacked`), a file in a historical layout, malformed/non-observation
structure, an input outside a recognised current observation, and unsafe
symbolic-link paths. The diagnostic must state why inference failed and direct
the user to supply `OUTPUT_TIFF` explicitly. A rejected inference is an
operational error (exit code `1`), not a command-line usage error. It must not
invoke conversion or create `tiff_images` directories.

## 6. Batch command contract

The grammar becomes:

```text
seestar-toolkit convert-batch INPUT_DIR [OUTPUT_DIR]
```

For a recognised current archive observation, all of these input forms resolve
the source to exactly `observation_NN/fits_images/lights/`:

```text
observation_NN/
observation_NN/fits_images/
observation_NN/fits_images/lights/
```

This source-resolution shorthand is approved whether `OUTPUT_DIR` is supplied
or omitted. With a supplied output, use that output path unchanged. With no
output, infer `observation_NN/tiff_images/lights/`.

For an ordinary non-archive directory, an omitted `OUTPUT_DIR` is syntactically
valid: attempt archive destination inference first. When that inference is
unavailable, report a clear operational error explaining that an explicit
`OUTPUT_DIR` is required and return exit code `1`, not `2`. A supplied output
uses the directory unchanged. Do not make ordinary directories archive-like by
inspecting their FITS contents. The command remains flat and does not traverse
unrelated directories, archive ancestors, stacks, TIFFs, or other observations.

If an archive-form input maps to a recognised observation but its canonical
lights directory is missing, report a clear operational error. If it exists
but has no eligible filename extensions, report that no eligible FITS files
were found, classify the batch as `FAILED`, return exit code `1`, and do not
create `tiff_images/lights`.

## 7. Inferred destination and collision handling

The sole inferred destination directory is:

```text
observation_NN/tiff_images/lights/
```

It may already exist, may contain TIFF files, and need not be empty. The
implementation must not examine or interpret unrelated entries under
`tiff_images/`. If either inferred directory component is absent, create only
the required path, only once a valid conversion requires it. Report creation
failures. Never create an empty inferred TIFF directory for an empty batch, an
invalid FITS input, an unsupported FITS input, or an inference failure. Never
replace an existing file or directory while creating those paths.

Existing standalone TIFF writer semantics remain authoritative in every mode:

- never overwrite an existing TIFF;
- existing identical and differing TIFFs both fail as collisions;
- a destination path occupied by a directory fails;
- perform no digest comparison, automatic skipping, automatic renaming, or
  replacement.

For batch processing, report each collision or other per-file failure and
continue with independent remaining inputs. Any failure makes the command exit
with the existing operational-failure code.

## 8. Reporting and diagnostics

On single-file success, preserve:

```text
Created TIFF: ...
```

For archive-aware batch execution with inferred output, report the inferred
output directory once. Retain existing per-file reporting and batch summary
information. The final report must distinguish complete `SUCCESS`, `PARTIAL
SUCCESS`, and `FAILED` outcomes consistently with current batch conventions.
Complete success has one or more conversions and no failures and returns exit
code `0`. Partial success has at least one converted file and at least one
failed file and returns exit code `1`. Failed has no successful conversions and
at least one failure and returns exit code `1`. An empty batch must report that
no eligible FITS files were found, is `FAILED`, returns exit code `1`, and
creates no inferred TIFF directory.

All inference errors must explain both the structural reason and that an
explicit output destination can be supplied. Existing explicit-output failures
retain their current diagnostics and status meaning.

and must assert public or structured behaviour rather than private incidental
details.

## 12. Formal closure criteria

ENH-004 may close only when:

1. T01–T32 have reviewed implementation/test evidence or an explicitly agreed
   disposition.
2. Both commands implement only the approved optional-output and archive-input
   shorthand contracts; explicit-output behaviour remains compatible.
3. Archive recognition is structural, current-layout-only, safe against
   symbolic-link/path escapes, and performs no unauthorised ancestor, index,
   stack, or FITS-content validation.
4. Directory creation is lazy and no empty inferred TIFF directory is left for
   empty, invalid, unsupported, or inference-failure cases.
5. TIFF collision protection and the conversion engine remain unchanged, with
   partial and complete batch failure continuing independent files where
   applicable and returning exit code `1`; empty batches report no eligible
   FITS and are failed with exit code `1`.
6. Required focused, regression, full-suite, Ruff/formatting, CLI-help, and
   changed-file checks pass and are evidenced without invented results.
7. Required user/development documentation accurately describes the approved
   final behaviour.
8. The user reviews the final diff and controls all Git integration and any
   release action.
