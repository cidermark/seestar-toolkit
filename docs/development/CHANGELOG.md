## Commit Naming Recommendations

- Functional stages: `2.2a`, `2.2b.1`, etc.
- Infrastructure: `INF-*`
- Documentation: `DOC-*`
- Test infrastructure: `TEST-*`

## Standard Change Workflow

Each functional stage should:

1. Begin from a passing build.
2. Have a change document in `docs/development/change_documents/`.
3. Identify exact files, classes/functions and changes.
4. Run `ruff check .`.
5. Run `pytest`.
6. Review `git diff`.
7. End with a passing build.
8. Commit the completed stage.
9. Record the commit in this changelog.

Stage markers:

``` text
====================================================================================================
===                                                                                              ===
===                            STARTING STAGE x.y.z                                              ===
===                                                                                              ===
====================================================================================================
```

``` text
====================================================================================================
===                                                                                              ===
===                            STAGE x.y.z COMPLETE                                              ===
===                                                                                              ===
====================================================================================================
```

Detailed implementation instructions belong in individual stage change
documents rather than in this changelog.
